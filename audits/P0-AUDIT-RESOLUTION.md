# P0 resolution plan — Foundations acceptance bottleneck

- **Date:** 2026-10-11
- **Branch:** `arena/07fdceae-swf-forge`
- **Companion audit:** [`P0-AUDIT.md`](P0-AUDIT.md).
- **Status:** plan only; no finding is resolved by writing this document. P0 remains **In progress**.
- **Scope:** close the P0 gaps against roadmap §6, `IMPL-010` §§8–11, SWF-R001, and `WP-010-01…12`. This is not authorization to change AVM1 behavior, P1+ phase ownership, or unrelated parser semantics.

## 1. Instructions for the resolving agent

1. Read the companion audit, roadmap P0 exit criteria, `IMPL-010` §§3–11, SWF-R001, and this plan before changing code.
2. Keep the existing test IDs and requirements. A citation, a passing general suite, or a similar test is not closure unless it asserts the full obligation named by the owning spec.
3. Reuse existing test support where possible. Do not add external SWF binaries or treat public availability as licensing permission.
4. First add or correct tests. Change production readers only when a new acceptance test demonstrates a behavior defect; record any behavior/spec divergence in `IMPL-010`'s changelog and errata as appropriate.
5. Keep P0 work scoped to binary IO, primitive records, diagnostics, and their acceptance harness. Do not pull in P1 container work, P5 AVM1 behavior, P6/P7, or runtime implementation.
6. Do not mark P0 Completed until the final closeout checklist in §4 passes and a fresh P0 audit records the evidence.

## 3. Guardrails and non-substitutions

- Do not count `T-SWF-012`'s one-corpus fingerprint as `T-SWF-009`'s all-fixture comparison.
- Do not count `T-SWF-021`'s backing-buffer identity assertion as the 5 MiB copy budget or the 10⁶-read allocation counter.
- Do not count the `openSwf` 10⁴ mutation smoke as the P0 raw-reader fuzzer.
- Do not count the current `T-SWF-015` bit-width/bounds cases as later-record recovery, or the `T-SWF-016` class assertion as a code/offset assertion.
- Do not weaken or delete a vector, test ID, or requirement to make the matrix green. Document a true upstream/spec conflict through the established errata process.
- `IMPL-010` §10's `FLOAT16`/`SI24` questions remain explicit until resolved. P0 closure does not authorize P5 AVM1 semantics, byte-round-trip work, P6, or P7.
