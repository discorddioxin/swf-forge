# TST — Conformance, Testing, and Performance Gates

**Doc ID:** TST · **Status:** Draft 1.2 · **Normative:** yes

---

## 1. Scope

This document defines how we know the compiler and runtime are correct: the test taxonomy, the
fixture program, the oracle harness, the metrics and tolerances that decide pass/fail, the performance
gates, the browser matrix, and the acceptance criteria for the three compatibility tiers (ARCH-§6).

It exists because most of the hard behaviour in this project is *under-specified upstream*: the only
way to be right is to measure, and the only way to stay right is to measure automatically.

## 2. Test taxonomy

| Class | Purpose | Tools | Runs |
| --- | --- | --- | --- |
| **Unit** | Pure functions: parsers, coercions, matrices, resamplers, packers | `vitest` (node/browser) | every PR |
| **Golden** | Deterministic artefacts: emitted TS, atlases, manifests, decoded PCM | `vitest` + committed goldens | every PR |
| **Differential** | Compare against an oracle (independent AVM1 implementation or archival captures) | Playwright + oracle harness | `conformance` job |
| **Visual** | Rendered frames compared within a tolerance | Playwright + image diff | `browser`/`conformance` |
| **Audio** | Offline renders compared in the time/frequency domain | `OfflineAudioContext` + numeric analysis | `browser`/`conformance` |
| **Property** | Invariants over generated inputs (round-trips, idempotence) | custom generators | nightly |
| **Fuzz** | Robustness of parsers/decoders to hostile input | `swffuzz`, libFuzzer-style mutators | nightly + budget per PR |
| **Performance** | Frame budgets, memory, bundle size | harness + `vitest bench` | `perf` job |
| **Soak** | 30–60 min play-throughs: leaks, drift, thermal-style slowdown | Playwright + scripted input | nightly |
| **Integration** | Emitted project compiles, boots, and passes C1 | `swfforge build` + `vite build` + Playwright | `emit` job |

**TST-R001** Every normative requirement in the spec set MUST map to at least one test ID, or be
listed in that document's Decision register as unverifiable-so-far. An unmapped requirement is a
review blocker (`tools/spec-coverage` checks this and reports the percentage).

**TST-R002** Tests MUST be deterministic. Any test needing randomness takes a seeded generator;
any test needing time uses a virtual clock.

## 3. Fixture program

### 3.1 Fixture classes

| Class | Content | Purpose |
| --- | --- | --- |
| `synthetic` | Hand-authored SWFs generated by our own writer (no Adobe tools) | Unit-level precision: shapes, gradients, transforms, actions |
| `open` | Indie/CC-licensed AS1/AS2 games and demos, committed or fetched | Real-world coverage, redistributable |
| `archive` | Historically important SWFs, fetched by URL, not committed | Differential testing breadth (TST-§4) |

**TST-R003** `fixtures/synthetic/` MUST be generated from a small **SWF writer** we own
(`@swf-forge/testing/swf-writer`). Rationale: hand-writing a SWF in a hex editor is unauditable, and
using an Adobe-era authoring tool is impossible. The writer emits minimal, readable SWFs for one
feature each, and doubles as a documentation artefact (the test *states* what the byte pattern means).

```ts
// Example: the fixture for "two fills sharing an edge"
await writeSwf({ width: 200, height: 100, frameRate: 24 }, [
  defineShape(2, [
    solidFill(0xff0000), solidFill(0x0000ff),
    rect(0, 0, 100, 100), rect(100, 0, 200, 100),
  ], { fillRule: 'evenodd', sharedEdge: true }),
  placeObject(2, 1),
  showFrame(),
]);
```

**TST-R004** Every synthetic fixture MUST declare, in a `*.fixture.ts` header comment, the requirement
IDs it exercises. `tools/spec-coverage` MUST complain when a fixture cites an unknown ID.

**TST-R005** `fixtures/external/` entries have the form:

```jsonc
{ "id": "open.alien_hominid_demo", "url": "…", "sha256": "…", "bytes": 1234567,
  "license": "CC-BY-NC-ND-3.0 (fixture use only, not shipped)",
  "featureTags": ["stream-sound", "bitmap-heavy", "hitTest-shape"], "oracleVersion": "…" }
```

and the fetch script MUST verify the hash before use. Tests using external fixtures MUST be skipped
(not failed) when the corpus is absent, except in the `conformance` job (TST-R006).

**TST-R006** The `conformance` CI job MUST run with the full external corpus and MUST fail if any
declared fixture is missing (this is the job that guards fidelity, so it must not silently shrink).

### 3.2 The Appendix fixtures (App A–C)

**TST-R024** The Appendix A worked example MUST be a **committed, byte-exact** synthetic fixture:
the 79-byte file exactly as the appendix dumps it. Our writer MUST be able to emit those bytes, our
readers MUST reproduce every value the appendix annotates — version 3; `FileLength` 79; the header
`RECT` (`Nbits` 15, 0/11000/0/8000 twips = 550×400 px); `FrameRate` raw 3072 (12 fps); `FrameCount` 1;
the tag sequence `SetBackgroundColor`, `DefineShape` (**long header**, 35-byte body), `PlaceObject2`,
`ShowFrame`, `End`; `ShapeId` 1; the shape bounds and the single 20-twip black line style; the style
change (`StateLineStyle | StateMoveTo`, `MoveBits` 14, +4900/+1680 twips, line style 1) and the four
straight edges (+2320 vertical, −2880 horizontal, −2320 vertical, +2880 horizontal); the placement
(`PlaceFlagHasCharacter | PlaceFlagHasMatrix`, depth 1, character 1, empty matrix) — and re-emission
MUST be byte-identical. This is the only end-to-end byte-level example upstream provides; it is worth
more than fifty hand-made fixtures because it cannot drift from the specification.

**TST-R025** The reverse tag index (`APP-§2`) MUST be machine-checked against Appendix B: the same 65
`code → name` entries with no additions, omissions or renames. Every tag value *not* in that index
(today: 3, 16, 25, 27, 29–31, 38, 40–42, 44, 47, 49–55, 63, 67, 68, 72, 79–81, 85, 92, and anything
above 93) MUST take the unknown-tag path — skipped by length with `SF0104` (`IMPL-020`) — never guessed
from a nearby code.

**TST-R026** The Screen Video v2 default palette (`APP-§10.12`, shipped as a frozen table by
`IMPL-110` §6) MUST be machine-checked against Appendix C entry-for-entry in appendix order (128
values, `0x00RRGGBB`). The check is order-sensitive on purpose: a palette that is faithful as a *set*
but permuted produces wrong colours on every 7-bit pixel, and the upstream table's order is part of
the format.

## 4. Oracle harness

"Oracle" = an independent implementation whose observed behaviour defines truth. Two sources:

| Source | Use | Availability |
| --- | --- | --- |
| An archival, recorded run (frames + event traces + audio) captured once from a reference player | Primary baseline for **visual/audio** comparisons; stable over time | Committed as compact artefacts (PNG/WebP frames + hashes) |
| A live independent AVM1 implementation (an open-source player) | Differential **behavioural** comparisons: script outputs, timeline state, event ordering | Optional local dependency; not committed |

**TST-R007** We MUST NOT require Flash Player to run tests. Any modern environment cannot run it, and
a test suite that cannot run is worse than no test suite. Archival captures supply the fidelity
baseline; a live open-source player supplies behavioural differentials.

**TST-R008** Captures MUST be produced by a documented, repeatable procedure (`tools/oracle/capture.md`)
that fixes: stage scale, DPR, font set, seeded randomness, input script, frame indices, and audio
device configuration (offline render). A capture without a procedure is not evidence.

### 4.1 Differential protocol

```
for each fixture:
  1. Build with swf-forge (reproducible config).
  2. Run the emitted game in a headless browser with:
       - a scripted input sequence (pointer/key events at fixed frame indices),
       - a seeded RNG for AVM1-D06 behaviour,
       - the virtual clock pinned to the SWF frame rate.
  3. Record: per-frame screenshot at frames [0, 1, 2, 5, 10, 30, 60, 120, …],
              display-list dumps at those frames (structurally comparable tree),
              AVM1-visible state probes (a generated probe module reads variables at those frames),
              audio offline render (first N seconds),
              event trace (ordered list of host events delivered).
  4. Compare against the oracle capture with the metrics in TST-§6.
  5. Report a per-fixture scorecard with the exact failing frames and requirement IDs.
```

**TST-R009** State probes MUST be generated, not hand-written: for each fixture, the probe list is
derived from the variables that the fixture's script writes (`tools/oracle/probes.ts`). Hand-written
probes rot and bias the suite toward what we already tested.

**TST-R010** A differential run MUST be *reproducible down to the frame index*: no wall-clock
dependence, no `Math.random` (seeded), no dependence on font availability (bundled fonts only), and
no dependence on audio hardware (offline render).

### 4.2 What cannot be compared

| Aspect | Why | Substitute |
| --- | --- | --- |
| Exact GPU output | Different rasterisers | Tolerance metrics (TST-§6) |
| Flash's mixer output | Undocumented fixed-point internals | Scheduling/position assertions + loudness checks |
| Timing of asynchronous loads | Network | Virtual clock + synthetic latency injection |
| Device fonts | Unavailable/licensed | Substitution table + F4 declaration |
| Obsolete codecs (VP6/Nellymoser playback) | Not shipped | Decode-level comparison only |

## 5. Golden tests (build outputs)

**TST-R011** The compiler's outputs MUST be golden-tested in three layers:

| Layer | Golden | Update policy |
| --- | --- | --- |
| Emitted TypeScript | Full text of each emitted module for the synthetic corpus | Reviewed diff; changes require a rationale in the PR |
| Asset metadata | Manifest JSON (sorted, pretty) | Reviewed diff |
| Binary assets | `sha256` only (never committed bytes) | Hash pinned in a fixture record; regeneration script included |

**TST-R012** Golden updates MUST be a single command (`pnpm goldens:update`), and the resulting diff
MUST be small enough to read in review. If a change produces a 200-file diff, the PR MUST explain why
a broad change is correct (e.g. a deliberate hash-format change) or be rejected.

## 6. Metrics and tolerances

### 6.1 Visual

| Metric | Definition | Threshold | Applies to |
| --- | --- | --- | --- |
| `exact` | Pixel-identical RGBA | 100% | Integer-positioned, opaque, straight-edged fixtures |
| `SSIM` | Structural similarity, per channel, averaged | ≥ 0.995 (default), ≥ 0.985 for filter-heavy fixtures | Everything rendered |
| `pAlphaRMS` | RMS of alpha difference | ≤ 3/255 | Thin strokes, hairline, small text |
| `edgeShift` | Max distance (px) of a 0.5-alpha boundary between reference and candidate | ≤ 1 px | Geometry checks |
| `bboxDelta` | Bounding-box difference of non-transparent content | ≤ 1 px per side | Layout checks |

**TST-R013** Image comparisons MUST be performed after converting both images to the same
premultiplied-linear-free space (i.e., compare as authored sRGB bytes; AST-R011) and MUST report a
visual diff artefact (98th-percentile heat map) attached to the CI run, not just a number.

**TST-R014** Anti-aliasing differences MUST NOT be "fixed" by loosening thresholds globally: a
threshold is per fixture-subclass, declared in the fixture record, and justified by the fidelity level
(GFX-§13).

### 6.2 Audio

| Metric | Definition | Threshold |
| --- | --- | --- |
| `nullRMS` | RMS of (reference − candidate) after alignment | ≤ −60 dBFS for decoded-vs-source; ≤ −40 dBFS for encoded round-trips |
| `driftMs` | Position error between the timeline clock and the audio playhead | ≤ 12 ms (AUD-R064) |
| `clickDelta` | Max first-difference across a transition | ≤ 0.05 FS (AUD-R075) |
| `loudnessDelta` | Integrated LUFS difference for music | ≤ 0.5 LU when `loudness=off` |
| `alignmentFrames` | Sample offset of a marker impulse between reference and candidate | 0 frames |

### 6.3 Behavioural

| Metric | Definition | Threshold |
| --- | --- | --- |
| `stateDiff` | Number of probe values differing at a frame index | 0 (or listed in a fixture's accepted-divergence list) |
| `eventOrder` | Longest common subsequence match of event traces | 100% for Tier-1 events; ≥ 95% for Tier-3 |
| `frameCountDelta` | Difference in timeline frame indices reached by a script | 0 |
| `tierCoverage` | Fraction of emitted functions at T0/T1 vs T2 | Informational; a title with > 20% T2 needs review |

**TST-R015** Behavioural divergences MUST be *recorded*, not absorbed: a fixture may declare
`acceptedDivergences: [{ req: 'AVM1-D11', reason: '…' }]`, and the harness reports the count of
accepted divergences per fixture. A rising count is a red flag for review, and the total appears in
the release notes.

## 7. Performance gates

### 7.1 Baseline devices

| Class | Specification | Purpose |
| --- | --- | --- |
| `baseline-desktop` | 4-core x86, integrated GPU (Iris-class), 8 GB RAM, Chromium stable | Primary gate |
| `baseline-mobile` | 2020 mid-range Android, 4 GB RAM, Chromium stable | Mobile gate |
| `headless-ci` | CI runner, software rasteriser (SwiftShader) | Determinism/regression only, not budgets |

**TST-R016** Budget gates MUST run on `baseline-desktop` and `baseline-mobile`, never on the CI
runner (software rasterisation is not a representative GPU). CI runs deterministic *counters*
(draw calls, allocations, bundle bytes) on headless; the wall-clock budgets run in a scheduled job on
real devices (a device farm or a maintained local runner).

### 7.2 Scene set

| Scene | Composition | Gates |
| --- | --- | --- |
| `perf-static` | 800 static sprites, 4 atlases, no scripting | draw calls, triangles, steady-state CPU |
| `perf-vector` | 300 tessellated shapes with strokes and gradients, rotating | tessellation cost, GPU time |
| `perf-particles` | 2000 alpha quads, spawn/despawn churn | batching, uploads, zero allocations |
| `perf-text` | 40 dynamic text fields updating every frame | layout cost, upload churn |
| `perf-filters` | 6 filtered groups (blur/glow/bevel) animating | filter pass count, GPU time |
| `perf-audio` | 32 voices, 4 with envelopes, one streaming music track | mixer CPU, underruns |
| `perf-avm1` | 10 000 actions/frame, hot loops, property access | AVM1 throughput (AVM1-§12) |
| `perf-mixed` | A representative real game (from the `open` corpus) at 60 s | end-to-end frame time |

**TST-R017** Each scene MUST have a committed expectation file (`*.expect.json`) with counters and
budget-derived bounds. The harness MUST fail when a counter exceeds its bound, and MUST warn (not
fail) when wall-clock time exceeds by < 15% on `perf-mixed`.

| Counter | Bound (baseline-desktop) | Bound (baseline-mobile) |
| --- | --- | --- |
| `drawCalls` (perf-static) | ≤ 420 | ≤ 420 |
| `drawCalls` (perf-mixed, worst frame) | ≤ 900 | ≤ 500 |
| `tessellationMsPerFrame` (perf-vector, steady) | ≤ 0.5 | ≤ 1.0 |
| `filterPasses` (perf-filters) | ≤ 24 | ≤ 12 |
| `mixerMsPerQuantum` (perf-audio) | ≤ 0.5 | ≤ 1.0 |
| `avm1MsPerFrame` (perf-avm1) | ≤ 1.0 | ≤ 2.5 |
| `heapGrowthBytesPerMinute` (all scenes) | ≤ 64 KB | ≤ 64 KB |
| `frameMsP95` (perf-mixed) | ≤ 12 ms | ≤ 20 ms |

**TST-R018** Perf regressions > 5% (counters) or > 10% (P95 frame time) versus `main` MUST fail the
`perf` job, with the offending scene and counter named in the failure.

### 7.3 Bundle budgets

**TST-R019** The bundle budget job (RT-§9) MUST measure, per emitted fixture project:
core runtime bytes, per-feature additions (interpreter, video, XMLSocket, BitmapData), and the emitted
game's own bytes after a stock `vite build`, against the budgets in RT-§9 and AST-§8.

## 8. Browser and device matrix

| Engine | Versions | Scope |
| --- | --- | --- |
| Chromium (desktop) | current stable, current−1 | Full suite |
| Firefox (desktop) | current stable, ESR | Full suite minus WebGPU-only paths |
| WebKit (desktop) | current stable (Playwright WebKit) | Full suite minus known engine limitations (documented) |
| Chromium (Android) | current stable | Mobile gates, touch input |
| Mobile Safari | current iOS | Smoke + audio unlock + touch (device farm) |

**TST-R020** Any test disabled for an engine MUST carry an `engine-skip` annotation with a reason and
an issue reference; skips MUST be listed in `reports/engine-matrix.md` so the matrix stays honest.

**TST-R021** Every release MUST publish the matrix with pass/fail/skip counts. A skip that silently
grows across releases is a bug in the process, not a fact of life.

## 9. Acceptance criteria

### 9.1 Per-tier gates (ARCH-§6)

| Tier | Gate |
| --- | --- |
| **C0 Loads** | `swfforge verify` clean; emitted project compiles with zero suppressions; boots and presents frame 1 within budget |
| **C1 Plays** | Scripted 60-frame play-through with zero errors, zero denied-URL surprises (i.e., all denied URLs were declared at build time), zero placeholder assets rendered (placeholder usage is instrumented and asserted) |
| **C2 Faithful** | All fixtures at the title's feature tags pass their declared metrics; accepted divergences are listed with decision IDs; performance within budget on both baselines |

### 9.2 Per-subsystem acceptance (v1 definition of done)

| Subsystem | Done means |
| --- | --- |
| SWF (SWF) | All T-SWF tests pass; fuzzing 24 h without crash; 100% tag coverage for AVM1-era tags |
| AVM1 (AVM1) | T-AVM1 suite passes; 15-digit formatting complete; tier report for the `open` corpus with ≤ 20% T2 |
| GFX (GFX) | T-GFX suite passes; budgets met on all scenes; context loss recovery verified |
| AUD (AUD) | T-AUD suite passes; drift ≤ 12 ms over 10 min; no clicks in the transition suite |
| AST (AST) | T-AST suite passes; atlas determinism; manifest schema validated by a published JSON Schema |
| RT (RT) | T-RT suite passes; dispose/leak audit clean; bundle budgets met |
| Compiler (CMP) | Determinism verified on the corpus; diagnostics all carry IDs; `verify` clean |

**TST-R022** The v1 release MUST NOT ship until each subsystem row above is satisfied or explicitly
deferred in the release notes with a named owner.

## 10. Reporting

Every CI run MUST publish:

| Artefact | Content |
| --- | --- |
| `conformance.json` | Per-fixture scorecard: metrics, thresholds, pass/fail, accepted divergences |
| `visual-diffs/` | Heat maps for failing frames (retained 14 days) |
| `audio-diffs/` | Spectrograms and null-test plots for failures |
| `perf.json` | Counters per scene, with deltas vs `main` |
| `budgets.json` | Bundle, texture, audio, manifest bytes |
| `spec-coverage.json` | Requirement → test mapping, with unmapped requirements listed |

**TST-R023** Failing conformance runs MUST attach the *first* divergence with enough context to
reproduce (`fixture id, frame index, metric, diff artefact, build hash, oracle capture hash`).

Test and gate ids cited by the harness implementation (`IMPL-140`):

| ID | Fixture/gate | Pass condition |
| --- | --- | --- |
| `T-TST-001` | Metric self-check | every metric is run against a deliberately broken input; a metric that passes it fails the pipeline |
| `T-TST-002` | Waiver expiry | an expired waiver fails the gate; waivers are the only legitimate way to pass a failing gate |
| `T-TST-003` | Report completeness | every `[verify]` item appears in the run summary, with unmapped requirements listed |
| `T-TST-004` | Appendix A fixture | the 79-byte worked example round-trips byte-for-byte and every annotated field is asserted (`TST-R024`) |
| `T-TST-005` | Appendix B tag index | `APP-§2` equals the appendix's 65 `code → name` entries; unassigned codes are skipped as unknown tags (`TST-R025`) |
| `T-TST-006` | Appendix C palette | the Screen Video v2 palette matches the appendix entry-for-entry in appendix order, 128 values (`TST-R026`) |

## 11. Decision register

| ID | Decision | Default | Verification | Notes |
| --- | --- | --- | --- | --- |
| TST-D01 | Committed goldens vs generated-on-demand | Committed (reviewable) | TST-R011 | Faster CI, real review value |
| TST-D02 | Oracle for visual baselines | Archival captures | TST-R008 | Live Flash unavailable |
| TST-D03 | Differential oracle for behaviour | Optional open-source player, non-blocking by default | TST-R007 | Used for investigation, gated in `conformance` where stable |
| TST-D04 | Default SSIM threshold | 0.995 | TST-R014 | Per-fixture overrides allowed with justification |
| TST-D05 | Frame sampling indices | 0,1,2,5,10,30,60,120 then every 60 | TST-R009 | Catches both startup and long-run drift |
| TST-D06 | Perf job cadence | Every PR (counters), 4×/day (wall-clock) | TST-R016 | Cost vs coverage |
| TST-D07 | Fuzz budget per PR | 60 s per target | SWF-R046 | Nightly full corpus |
| TST-D08 | Soak duration | 45 min per title | ARCH-§9 | Catches leaks and drift |
| TST-D09 | Accepted-divergence budget per fixture | ≤ 3 entries, each with a decision ID | TST-R015 | Prevents drift accumulation |
| TST-D10 | Spec coverage gate | ≥ 95% of requirements mapped | TST-R001 | Unmapped requires a register entry |
